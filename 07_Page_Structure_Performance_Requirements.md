# Блок 7. Структура страниц, скорость и машиночитаемые данные

**Ответственный за диагностику:** координатор проекта.

**Техническое сопровождение:** Суперадмин — при необходимости уточнения механизмов формирования страниц.

**Ресурсы:** публичный сайт [https://stavrdoors.ru](https://stavrdoors.ru/), HTML-код страниц, инструменты браузера, PageSpeed Insights, Lighthouse, валидаторы структурированных данных и средства проверки HTTP-ответов.

**Назначение:** проверка технической структуры страниц, качества HTML, производительности, мобильной доступности и корректности представления информации для поисковых систем.

## 7.1. Необходимые доступы

Для первичной диагностики административные права не требуются.
Используются общедоступные страницы сайта и независимые инструменты проверки.
Настройки шаблонов, компонентов, SEO-параметров, кеширования и генерации структурированных данных исследуются в рамках блоков 1 и 4.
Дополнительные доступы запрашиваются только при выявлении вопросов, которые невозможно разрешить по публичным данным и уже полученной технической документации.

## 7.2. Структура HTML и SEO-элементы

Для основных типов страниц проверить:

1. **Title и meta description** — наличие, содержание, уникальность и соответствие назначению страницы.    
2. **H1–H6** — наличие основного заголовка, логичность иерархии, отсутствие необоснованных повторов.    
3. **Canonical** — наличие и корректность канонических URL, особенно для товаров, связанных с несколькими разделами.    
4. **Meta robots** — директивы индексирования и перехода по ссылкам.    
5. **Внутренние ссылки** — доступность навигации, хлебных крошек и переходов между связанными страницами.    
6. **Изображения** — наличие содержательных alt у информативных изображений, форматы, размеры и параметры загрузки.    
7. **HTML-содержимое** — доступность основных характеристик, описаний и ссылок в коде страницы.    
8. **Дублирование** — повторяющиеся элементы, шаблонные метаданные и альтернативные URL с одинаковым содержимым.    
9. **Мобильная версия** — корректность отображения, навигации и доступности основных элементов.    
10. **HTTP-ответы** — корректность статусов 200, 301, 302, 404 и поведения редиректов.    

## 7.3. Машиночитаемые данные

Проверить существующую разметку Schema.org и другие структурированные данные:

1. Наличие и типы разметки на разных страницах.    
2. Корректность синтаксиса и вложенности элементов.    
3. Соответствие разметки видимому содержимому.    
4. Правильность данных о компании, товарах, ценах, характеристиках и навигации.    
5. Отсутствие противоречий между разными форматами разметки.    
6. Результаты проверки применимыми валидаторами.    

**Важно:** JSON-LD не является обязательным форматом для всех страниц. Сначала проверяется существующая microdata-разметка и её пригодность для конкретных поисковых функций.

## 7.4. Скорость и производительность

Проверить основные типы страниц с помощью PageSpeed Insights и Lighthouse.

**Анализируемые показатели:**

1. Largest Contentful Paint (LCP).    
2. Interaction to Next Paint (INP), если доступны полевые данные.    
3. Cumulative Layout Shift (CLS).    
4. First Contentful Paint (FCP).    
5. Total Blocking Time (TBT) — в лабораторных измерениях.    
6. Объём и загрузка изображений, CSS и JavaScript.    
7. Блокирующие ресурсы и избыточные скрипты.    
8. Время ответа сервера и задержки загрузки.    
9. Отличия мобильных и настольных результатов.    

Разделять реальные пользовательские показатели и результаты лабораторных тестов. Не делать выводы по одному запуску инструмента.

## 7.5. Выборка страниц

Для диагностики сформировать репрезентативную выборку:

- Главная страница.    
- Основные разделы каталога.    
- Подразделы по назначению и функционалу.    
- Карточки товаров разных категорий.    
- Страницы проектов.    
- Информационные статьи и новости.    
- Страницы компании и контактов.   

Выборку уточнить после анализа структуры сайта и данных поисковых систем.

## 7.6. Формат фиксации результатов

Для каждой проверки сохранять:

- URL страницы.    
- Дату проверки.    
- Тип страницы.    
- Использованный инструмент.    
- Проверяемый параметр.    
- Фактический результат.    
- Выявленное отклонение.    
- Ссылку на отчёт или сохранённое доказательство.    
- Статус: подтверждено / требует проверки / проблема не обнаружена.    

**Форматы:** Markdown, CSV/XLSX, HTML, PDF, PNG/JPG — в зависимости от инструмента и характера результата.

## 7.7. Разграничение этапов

**Диагностика:** проверка HTML, метаданных, структуры страниц, разметки, мобильной доступности и производительности.

**Подготовка ТЗ:** определение причин подтверждённых проблем, затрагиваемых шаблонов и компонентов, формирование требований и критериев приёмки.

**Выполнение работ:** внесение согласованных изменений в шаблоны, настройки, контент и технические компоненты сайта.

**Приёмка:** повторная проверка изменённых страниц и контроль отсутствия новых ошибок на других страницах, использующих те же шаблоны.

## 7.8. Ожидаемый результат

Получены данные, позволяющие:

- Оценить качество технической структуры основных типов страниц.    
- Выявить проблемы метаданных, заголовков, canonical и внутренних ссылок.    
- Проверить корректность существующей структурированной разметки.    
- Определить основные причины недостаточной производительности.    
- Сформировать технические задания с конкретными URL, требованиями и критериями приёмки.    
- Создать воспроизводимую методику проверки страниц для последующего контроля исполнителей.
