# Блок 2. Поисковые системы — доступ к диагностике и статистике

**Ответственный:** Суперадмин / владелец соответствующих учётных записей<br>

**Ресурсы:**
- Яндекс Вебмастер — [https://webmaster.yandex.ru](https://webmaster.yandex.ru/)    
- Google Search Console — [https://search.google.com/search-console](https://search.google.com/search-console)<br>

**Назначение:** диагностика индексирования сайта, обработки XML-карт, поисковых запросов и технических проблем, выявленных поисковыми системами.

## 2.1. Яндекс Вебмастер

**Запрашиваемые права**

Предоставить отдельной учётной записи аудитора делегированный доступ к подтверждённому сайту `stavrdoors.ru`, достаточный для просмотра диагностических разделов и экспорта статистики, без необходимости изменения настроек сайта.

**Необходимые разделы:**

1. Диагностика сайта — ошибки, предупреждения, рекомендации.  
2. Индексирование — страницы в поиске, исключённые страницы, история обхода, статус URL.    
3. Файлы Sitemap — зарегистрированные XML-карты, даты обработки, ошибки.    
4. Поисковые запросы — показы, клики, CTR, позиции.    
5. Страницы в поиске — данные о представлении и доступности страниц.    
6. Ссылки — доступные отчёты о внешних и внутренних ссылках.    
7. Региональность и представление сайта — текущие настройки и доступные сведения.    
8. История уведомлений и существенных изменений.    

**Если доступ предоставить невозможно:**

Если доступ к Яндекс Вебмастеру предоставить невозможно, для согласованного списка URL предоставить результаты проверки: известна ли страница Яндексу, находится ли она в поиске, когда последний раз обходилась роботом, какой HTTP-ответ получен и имеются ли причины исключения из поиска. Формат — PDF, скриншоты или доступная выгрузка.

## 2.2. Google Search Console

**Запрашиваемые права**

Предоставить доступ к ресурсу `stavrdoors.ru` с ролью **Full user** для просмотра отчётов, экспорта данных и проверки URL.

Если предоставление Full user невозможно — роль Restricted user с дополнительными выгрузками и проверками силами владельца.

**Необходимые разделы:**

1. Performance / Эффективность — запросы, страницы, страны, устройства, показы, клики, CTR, позиции.    
2. Page indexing / Индексирование страниц — проиндексированные и исключённые URL, причины исключения.   
3. Sitemaps / Файлы Sitemap — зарегистрированные карты, статус обработки, ошибки.   
4. URL Inspection / Проверка URL — результаты проверки согласованного перечня страниц.   
5. Core Web Vitals / Основные интернет-показатели — доступные отчёты о пользовательском опыте.    
6. HTTPS — состояние соответствующего отчёта, если доступен.   
7. Enhancements / Улучшения — отчёты по структурированным данным, если формируются.   
8. Links / Ссылки — внутренние и внешние ссылки.    
9. Manual actions / Меры, принятые вручную, и Security issues / Проблемы безопасности.    

**Если доступ предоставить невозможно:**

Передать доступные выгрузки по перечисленным разделам в CSV/XLSX или Google Sheets, а для диагностических экранов без экспорта — PDF или скриншоты.

Для согласованного списка URL дополнительно предоставить результаты инструмента **URL Inspection (Проверка URL)** с указанием:

1. **Известна ли страница Google** — обнаружена ли она поисковой системой.   
2. **Проиндексирована ли страница** — может ли она участвовать в поисковой выдаче.    
3. **Причина отсутствия в индексе** — если страница не проиндексирована, какое объяснение показывает Google.   
4. **Дата последнего сканирования** — когда Googlebot последний раз посещал страницу, если эти сведения доступны.   
5. **Результат сканирования** — успешно ли Google получил страницу и какие проблемы обнаружил.   
6. **Разрешено ли индексирование** — нет ли ограничений со стороны robots.txt или директив noindex.   
7. **Канонический URL** — какой адрес указан владельцем сайта и какой Google выбрал основным.    
8. **Обнаружение страницы** — через какую XML-карту или ссылающиеся страницы Google мог найти URL, если эти сведения представлены в отчёте.    

**Формат:** PDF или скриншоты полного результата проверки каждого URL с указанием даты проверки.

Если страница не индексируется или данные отчёта неоднозначны, дополнительно предоставить результат **Test Live URL (Проверить опубликованный URL)** — проверки текущей версии страницы, доступной Google на момент теста.

## 2.3. Период предоставления данных

- Поисковая статистика — максимально доступный период, предпочтительно последние 16 месяцев.   
- Индексирование, sitemap, технические ошибки — актуальное состояние и доступная история.   
- Поисковые запросы — с разбивкой по датам, страницам, устройствам и странам/регионам, если такие данные доступны.   
- Уведомления и история проблем — за последние 12 месяцев либо максимально доступный период.

## 2.5. Разграничение этапов

**Диагностика:** анализ состояния индекса, ошибок, поисковых запросов и обработки XML-карт.

**Подготовка ТЗ:** определение конкретных URL, групп страниц и технических причин проблем, формирование измеримых критериев исправления.

**Выполнение работ:** изменения на сайте выполняются отдельно; действия в кабинетах поисковых систем — только по согласованному ТЗ и с необходимыми полномочиями.

**Приёмка:** повторная проверка URL, обработки sitemap, диагностических сообщений и динамики индексирования. Изменения поисковых показателей оцениваются с учётом задержек обработки поисковыми системами.

## 2.6. Ожидаемый результат

Получены данные, позволяющие установить:

- Какие страницы сайта известны поисковым системам и какие включены в индекс.   
- Какие технические проблемы мешают обходу или индексированию.  
- Как поисковые системы обрабатывают sitemap.  
- По каким запросам сайт получает показы и переходы.  
- Какие страницы и направления требуют приоритетного внимания.    
- Как независимо проверить результаты последующих исправлений.
